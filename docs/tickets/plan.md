# AI Chef — Тікети для розробки

> Проєкт хакатону. 1 розробник, ~1 місяць. Стек: PHP, Laravel, PostgreSQL, Nginx, Anthropic Claude API.

---

## Зведення прийнятих рішень

| Аспект | Рішення |
|---|---|
| **Скоуп MVP** | Усі 3 блоки з ТЗ (профілі сім'ї + комора + AI-генерація + фото-розпізнавання) |
| **Авторизація** | Laravel Breeze (email + password) |
| **Модель сім'ї** | Окремі члени з вільнотекстовими полями. Перед генерацією юзер обирає, для кого готує — обмеження комбінуються через AND |
| **Алергії/дієти** | Вільний текст (без пресетів) |
| **Комора** | Структуровано: `name + quantity (decimal) + unit`. Без термінів придатності |
| **Одиниці виміру** | г, кг, мл, л, шт, ст.л., ч.л., склянка |
| **Довідник продуктів** | Вбудований ~150 продуктів (seeder) + дозвіл custom |
| **AI-провайдер** | Anthropic Claude (Haiku 4.5 для більшості, Sonnet 4.6 за потреби якості) |
| **Стратегія AI** | Один мультимодальний LLM на все (фото + рецепти) |
| **Фото страви** | Без фото — лише назва + emoji |
| **Кеш AI-викликів** | Хеш від (комора + обрані члени) → JSON-відповідь |
| **Списання після приготування** | Екран підтвердження з редагуванням кількостей |
| **Історія** | Повноцінна + обране |
| **Дисклеймер** | Видимий на UI: "AI може помилитися, перевіряйте склад страв" |

## Епік 0: Фундамент (3-4 дні)

- **0.1 Ініціалізація Laravel-проєкту**
  Створити свіжий Laravel 11/12 проєкт, налаштувати git-репо, додати .gitignore, README з кроками запуску.

- **0.2 Docker-compose для розробки**
  Підняти PHP-FPM, PostgreSQL і Nginx через docker-compose. Перевірити, що `php artisan migrate` працює з контейнерної БД.

- **0.3 Налаштування Laravel Breeze (email + password)**
  Встановити Breeze з Blade-стеком, мігрувати таблицю `users`, перевірити флоу реєстрації/логіну/логауту.

- **0.4 Базовий лейаут і навігація**
  Створити app-layout з шапкою, навігацією (Комора / Сім'я / Рецепти / Історія), футером і Tailwind-стилями.

- **0.5 Конфіг Anthropic API**
  Додати `ANTHROPIC_API_KEY` в `.env` і `.env.example`, створити `config/services.php` секцію для anthropic.

- **0.6 Глобальний дисклеймер у лейауті**
  Додати в футер/шапку видиме повідомлення про те, що AI може помилятися і користувач повинен сам перевіряти склад страв на алергени.

## Епік 1: Комора — ручний ввід (4-5 днів)

- **1.1 Міграція таблиці `ingredients` (довідник)**
  Поля: `id`, `name` (ukr), `category` (опціонально: м'ясо/молочка/овочі/...), `is_custom` (false для seed-даних), `created_by_user_id` (nullable для custom).

- **1.2 Сидер довідника інгредієнтів (~150 продуктів)**
  Згенерувати через Claude список найпопулярніших продуктів української кухні з категоріями, записати в `database/seeders/IngredientSeeder.php`.

- **1.3 Міграція таблиці `pantry_items`**
  Поля: `id`, `user_id`, `ingredient_id` (FK), `quantity` (decimal 10,3), `unit` (enum: g/kg/ml/l/pcs/tbsp/tsp/cup), `created_at`, `updated_at`.

- **1.4 Eloquent-моделі `Ingredient` та `PantryItem`**
  Зв'язки: `User hasMany PantryItems`, `PantryItem belongsTo Ingredient`. Скоуп `forUser()`.

- **1.5 Сторінка перегляду комори (index)**
  Список поточних позицій з кількостями і кнопками edit/delete. Якщо порожня — empty state з закликом додати.

- **1.6 Форма додавання позиції в комору**
  Поле "інгредієнт" з autocomplete по таблиці `ingredients` (jQuery UI або Alpine.js + endpoint `/ingredients/search?q=...`). Поля кількості і dropdown одиниць.

- **1.7 Створення custom-інгредієнта на льоту**
  Якщо юзер ввів назву, якої нема в довіднику — після підтвердження створюємо запис в `ingredients` з `is_custom=true` і прив'язуємо до позиції комори.

- **1.8 Редагування і видалення позиції комори**
  Edit-форма (та сама, що й add) і delete з підтвердженням-модалкою.

- **1.9 Валідація форми комори**
  Quantity > 0, unit ∈ allowed list, ingredient_name required, max length 100.

## Епік 2: Профілі членів сім'ї (2-3 дні)

- **2.1 Міграція таблиці `family_members`**
  Поля: `id`, `user_id`, `name`, `favorite_products` (text, nullable), `disliked_products` (text, nullable), `allergies_and_diets` (text, nullable).

- **2.2 Eloquent-модель `FamilyMember`**
  Зв'язок з User, `forUser()` scope.

- **2.3 Сторінка списку членів сім'ї**
  Картки з ім'ям і короткими тегами обмежень. Empty state.

- **2.4 Форма додавання/редагування члена сім'ї**
  Ім'я + три textarea (улюблене / неулюблене / алергії та дієти) з підказками-плейсхолдерами.

- **2.5 Видалення члена сім'ї**
  З підтвердженням і захистом від видалення останнього (опціонально — або дозволити, бо рецепт можна для "себе").

## Епік 3: AI Core — генерація рецепту (5-7 днів) ⭐ найважливіше

- **3.1 Міграція таблиці `recipes`**
  Поля: `id`, `user_id`, `name`, `ingredients_json`, `steps_json`, `kbju_json`, `pantry_snapshot_json` (що було в коморі при генерації), `selected_family_members_json`, `status` (generated/cooked), `is_favorite`, `cooked_at`, `created_at`.

- **3.2 Міграція таблиці `recipe_cache`**
  Поля: `cache_key` (string, indexed, primary), `response_json`, `model_used`, `created_at`. TTL контролюємо через created_at + cleanup-команду.

- **3.3 Service `ClaudeService`**
  Обгортка над Anthropic API: метод `generateText(messages, system)` і `generateFromImage(images, prompt)`. Обробка retry, timeouts, error logging.

- **3.4 Service `RecipePromptBuilder`**
  Метод приймає `User`, масив обраних `FamilyMember`-ів і повертає system + user prompts. Включає інструкції: "повертай JSON-схему", "інтерпретуй алергії широко", "одиниці — як у коморі".

- **3.5 Recipe JSON schema**
  Зафіксувати очікувану структуру відповіді Claude: `{name, description, ingredients: [{name, quantity, unit, in_pantry: bool}], steps: [], kbju: {kcal, protein, fat, carbs}, servings}`. Документація — в коді як константа.

- **3.6 Парсер відповіді Claude + валідація схеми**
  Розбирає JSON, перевіряє наявність обов'язкових полів, відкидає неповні відповіді (з retry).

- **3.7 Сторінка генерації рецепту**
  Чекбокси з членами сім'ї (за замовчуванням усі), показ поточної комори, велика кнопка "Згенерувати рецепт".

- **3.8 Endpoint генерації + Queue Job**
  Виклик Claude в `RecipeGenerationJob` (бо може зайняти 10+ сек). UI показує спіннер з polling-ом або redirect-ом після завершення.

- **3.9 Логіка кешу**
  Хеш від `(sorted pantry items, sorted selected family member ids, their constraint hashes)`. Перед API-викликом дивимось у кеш, після успішного — зберігаємо.

- **3.10 Картка рецепту (UI)**
  Відображення згенерованого: назва, опис, інгредієнти (з відміткою "є в коморі" / "треба купити"), покрокові інструкції, КБЖУ-блок, кнопки "Приготовано" і "В обране".

- **3.11 Обробка помилок генерації**
  Якщо API впав / модель повернула невалідний JSON / timeout — friendly error з кнопкою "Спробувати ще раз".

- **3.12 Rate limiting на генерацію**
  Laravel throttle: max 10 генерацій на годину на юзера для захисту від bug-loop і випадкового спаму.

## Епік 4: "Приготовано" → списання з комори (2-3 дні)

- **4.1 Кнопка "Приготовано" на картці рецепту**
  Веде на сторінку підтвердження списання, не списує одразу.

- **4.2 Сторінка підтвердження списання**
  Список інгредієнтів рецепту, які є в коморі (по `name + unit` match), з полями кількості (передзаповнені сумами з рецепту, але редаговані).

- **4.3 Service `PantryDeductionService`**
  Логіка: для кожного підтвердженого продукту знайти в коморі, відняти кількість. Якщо стає <= 0 — видалити запис. Атомарно (DB transaction).

- **4.4 Оновлення статусу рецепту**
  Після підтвердження — `recipes.status = 'cooked'`, `cooked_at = now()`. Redirect на детальну сторінку рецепту з повідомленням "Готово, комору оновлено".

---

## Епік 5: Історія та обране (2-3 дні)

- **5.1 Сторінка історії рецептів**
  Список усіх згенерованих рецептів юзера, відсортований за датою. Тег статусу (generated/cooked) і фільтр за статусом.

- **5.2 Детальна сторінка рецепту з історії**
  Та сама картка, що й після генерації, але з даних БД. Кнопка "Приготувати знову" (працює як новий "Приготовано").

- **5.3 Тогл "В обране" + endpoint**
  Серце-іконка на картці і в історії. Toggle через AJAX, оновлює `is_favorite`.

- **5.4 Сторінка обраних рецептів**
  Окрема сторінка / фільтр історії за `is_favorite=true`.

## Епік 6: Фото-розпізнавання комори (5-7 днів) ⚠ ризиковий блок

- **6.1 Сторінка завантаження фото**
  Upload-форма з підтримкою camera capture (`<input type="file" accept="image/*" capture="environment">` для мобільного). Дозволяти 1-3 фото.

- **6.2 Валідація завантажених фото**
  Max 5 МБ кожне, max 3 файли, формати jpeg/png/webp. Показ прев'ю перед відправкою.

- **6.3 Service `PhotoRecognitionService`**
  Бере зображення (base64 або URL), формує мультимодальний запит до Claude з промптом "перерахуй продукти на фото в JSON-форматі: [{name, estimated_quantity}]". Повертає масив.

- **6.4 Сторінка підтвердження розпізнаних продуктів**
  Список того, що Claude розпізнав, з полями редагування (назва, кількість, одиниця). Чекбокси "додати в комору", кнопка видалення зайвого.

- **6.5 Меппінг розпізнаних назв на довідник**
  Для кожної розпізнаної назви шукаємо в `ingredients` (LIKE або similar). Якщо знайшли — використовуємо існуючий ID. Якщо ні — флаг "буде створено custom".

- **6.6 Збереження підтвердженого списку в комору**
  Після підтвердження — bulk-create позицій комори з обраних, custom-інгредієнти створюються автоматично.

## Епік 7: Поліровка і деплой (3-4 дні)

- **7.1 Перевірка мобільної адаптивності**
  Пройтись по всіх сторінках на 375px шириною. Особлива увага: завантаження фото, форми комори, картка рецепту.

- **7.2 Empty states на всіх списках**
  Комора, члени сім'ї, історія, обране — кожен список з красивим заглушком + CTA-кнопкою.

- **7.3 Кастомні error-сторінки 404 і 500**
  В стилі продукту, не дефолтний Laravel-екран.

- **7.4 Nginx-конфіг для продакшну**
  Reverse proxy на php-fpm, gzip, cache headers для статики, ліміт upload-розміру (ALLOW 5MB+ для фото).

- **7.5 Деплой на VPS або PaaS**
  Hetzner/DigitalOcean або Render/Fly.io. Налаштувати SSL (Let's Encrypt), env-змінні, queue worker як service.

- **7.6 Демо-сидер з прикладними даними**
  Окремий seeder, що створює тестового юзера з 3 членами сім'ї, заповненою коморою і парою згенерованих рецептів — для швидкої демонстрації журі.

- **7.7 Фінальний README**
  Скріншоти, опис фіч, інструкція запуску локально, посилання на live-демо, технічний стек.

## Послідовність роботи (рекомендація)

```
Тиждень 1: Епік 0 → Епік 1 → Епік 2
Тиждень 2: Епік 3 (фокус!) → початок Епіку 4
Тиждень 3: Епік 4 → Епік 5 → Епік 6
Тиждень 4: завершення Епіку 6 → Епік 7 → buffer для bugfix-ів
```

**Принцип:** після кожного епіку має бути робочий, демонстрабельний шматок продукту. Якщо щось іде повільніше — Епік 6 (фото) можна відрізати, MVP від цього не помре.

## Що НЕ входить в скоуп MVP (для майбутнього)

- Терміни придатності інгредієнтів
- Список покупок з "докупити" продуктів
- Шейринг рецептів між юзерами
- Інтеграція з холодильниками/Smart Home
- Генерація фото готових страв через AI
- Telegram-бот / мобільний додаток
- Багатомовність (поки тільки українська)
- Соцлогіни (Google/Apple)
