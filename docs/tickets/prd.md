# AI Chef — Зведене ТЗ з прийнятими рішеннями

> Документ об'єднує оригінальне ТЗ з рішеннями, прийнятими під час планування. Це "джерело правди" для розробки.

---

## 1. Загальна інформація

**Назва:** AI Chef
**Тип:** вебдодаток (хакатон-проєкт ліцею)
**Мета:** допомогти користувачам генерувати рецепти страв на основі наявних інгредієнтів (введених вручну або розпізнаних AI з фото) з урахуванням вподобань і харчових обмежень членів сім'ї.

**Команда і таймлайн:**
- 2 розробник
- ~1 місяць на розробку
- Пріоритет демо: **корисність для реального юзера**

---

## 2. Стек і архітектура

| Шар | Технологія |
|---|---|
| Бекенд (мова) | PHP 8.x |
| Фреймворк | Laravel 11/12 |
| База даних | PostgreSQL |
| Фронтенд | Server-Side Rendering (Blade-шаблони) + HTML/CSS/JS (мінімально, для камери і завантаження фото) |
| Вебсервер / Reverse Proxy | Nginx |
| Авторизація | Laravel Breeze (email + password) |
| AI-провайдер | **Anthropic Claude API** (єдина інтеграція) |
| Модель за замовчуванням | Claude Haiku 4.5 (швидка, дешева, мультимодальна) |
| Модель для якісної генерації | Claude Sonnet 4.6 (за потреби) |
| Контейнеризація | Docker + docker-compose |

**Відмінність від оригінального ТЗ:** замість зв'язки Google Cloud Vision + окремий LLM використовуємо **один мультимодальний Claude** для всіх AI-задач (розпізнавання фото, генерація рецептів, КБЖУ). Це спрощує інтеграцію (один ключ, одна обробка помилок) і покращує точність розпізнавання продуктів.

## 3. Функціональні вимоги

### 3.1. Кабінет сім'ї (профілі)

**Зберігаємо для кожного члена сім'ї:**
- Ім'я
- Улюблені продукти (вільний текст)
- Неулюблені продукти (вільний текст)
- Алергії та дієти (вільний текст в одному полі — без пресетів)

**Логіка вибору "для кого готуємо":**
Перед кожною генерацією рецепту юзер обирає чекбоксами, для кого готує сьогодні. Обмеження обраних членів **комбінуються через AND** (рецепт має задовольняти всі алергії і дієти всіх обраних).

**Важливо для AI-промпту:** інструкція "інтерпретуй алергії широко". Якщо юзер написав "горіхи" — AI має виключити арахіс, кешью, фундук, мигдаль і т.д.

**Дисклеймер на UI:** видиме повідомлення "AI може помилитися, перевіряйте склад страв самостійно" (особливо важливо через алергії).

---

### 3.2. Управління інгредієнтами (комора)

**Модель даних позиції комори:**
- `name` — назва (через довідник або custom)
- `quantity` — число (decimal)
- `unit` — одиниця виміру (enum)

**Допустимі одиниці виміру:**
`г`, `кг`, `мл`, `л`, `шт`, `ст.л.` (столова ложка), `ч.л.` (чайна ложка), `склянка`

**Без термінів придатності** (виключено зі скоупу).

**Довідник продуктів:**
- Маленький вбудований каталог ~150 типових продуктів української кухні (засіюється через Laravel seeder)
- Поле введення з autocomplete по довіднику
- Якщо юзер вводить продукт, якого нема в довіднику — створюється як **custom** (з прапорцем)

**Способи додавання продуктів:**

1. **Ручне введення** — форма з autocomplete + поля кількості та одиниці.
2. **Через фото** — юзер фотографує холодильник/полицю, мультимодальний Claude повертає список розпізнаних продуктів. Юзер бачить розпізнаний список, може **редагувати, видалити окремі позиції або додати кількість** перед збереженням у комору.
    - Якщо AI розпізнав продукт, якого нема в довіднику → автоматично додаємо як custom.
    - Ліміти: до 3 фото за раз, до 5 МБ кожне, формати jpeg/png/webp.

---

### 3.3. Генерація рецептів (AI Core)

**Вхід для AI:**
- Поточний стан комори (з кількостями і одиницями)
- Обмеження обраних членів сім'ї (алергії, неулюблені, улюблені)

**Інструкції в промпті:**
- Інтерпретуй алергії широко
- Повертай інгредієнти рецепту в **тих самих одиницях**, що подані в коморі
- Дотримуйся структурованого JSON-формату відповіді
- Дозволено пропонувати 1-2 базові інгредієнти, яких нема в коморі (сіль, олія, спеції) — позначай їх як `in_pantry: false`

**Структура згенерованого рецепту (JSON-схема):**
```
{
  name: string,
  description: string,
  ingredients: [
    { name, quantity, unit, in_pantry: boolean }
  ],
  steps: [string],
  kbju: { kcal, protein, fat, carbs },  // на порцію
  servings: number
}
```

**Картка рецепту в UI:**
- Назва і опис страви
- **Без фото готової страви** (тільки emoji-акцент і красива типографіка)
- Список інгредієнтів з відміткою "є в коморі" / "треба купити"
- Покрокові інструкції приготування
- Розрахунок КБЖУ на порцію
- Кнопки: **"Приготовано"** і **"В обране"**

**Кешування AI-викликів:**
Для економії API-витрат: хеш від `(відсортована комора + обрані члени сім'ї + їхні обмеження)` → JSON-відповідь. Перед викликом API дивимось у кеш.

**Rate limiting:**
Max 10 генерацій на годину на юзера (захист від bug-loop і випадкового спаму).

---

### 3.4. Цикл "Приготовано" → списання з комори

**Процес:**
1. Юзер натискає **"Приготовано"** на картці рецепту.
2. Відкривається **екран підтвердження** зі списком інгредієнтів рецепту, які є в коморі. Кількості передзаповнені, але **редаговані**.
3. Юзер може скоригувати фактично використане і натискає "Підтвердити".
4. Система атомарно віднімає кількості з комори (якщо стає <= 0 — позиція видаляється).
5. Рецепт переходить у статус `cooked`, фіксується `cooked_at`.

**Чому з підтвердженням, а не автоматично:** обхід проблем з конверсіями одиниць між рецептом і коморою + чесніше для юзера ("я з'їв стільки, скільки реально з'їв").

---

### 3.5. Історія та обране

- Усі згенеровані рецепти зберігаються в БД, прив'язані до юзера.
- Сторінка **історії** з фільтром за статусом (generated / cooked).
- Тогл **"в обране"** (іконка серця) на картці і в історії.
- Окрема сторінка / фільтр **"Обрані рецепти"**.
- З історії можна "приготувати знову" — запускає новий цикл списання з поточної комори.

## 4. Нефункціональні вимоги і інфраструктура

| Аспект | Рішення |
|---|---|
| Auth | Laravel Breeze (email + password). Без OAuth і magic-link на MVP. |
| Локалізація | Тільки українська |
| Адаптивність | Mobile-first (бо головна фіча — фото з камери) |
| Кеш AI | Хеш-кеш в окремій таблиці `recipe_cache` |
| Rate limit | Laravel throttle middleware (10 генерацій/год) |
| Queue | Laravel queues для AI-викликів (бо вони тривалі) |
| Деплой | VPS (Hetzner/DigitalOcean) або PaaS (Render/Fly.io) + Let's Encrypt SSL |

## 5. Що НЕ входить в MVP (для майбутнього)

Свідомо виключено для дотримання таймлайну:

- Терміни придатності продуктів
- Список покупок з "докупити" інгредієнтами
- Генерація фото готових страв через AI
- Соціальний логін (Google/Apple)
- Шейринг рецептів між юзерами
- Багатомовність (UA-only)
- Telegram-бот / мобільний додаток
- Інтеграція зі смарт-холодильниками
- Складні дієтологічні підрахунки (тижневі плани, баланс БЖУ за день)

## 6. Принципи, які варто пам'ятати при розробці

1. **Якість рецептів важливіша за крутість AI-фішок.** Краще витратити день на доопрацювання промпту, ніж на анімовану іконку.
2. **Безпека алергій — пріоритет.** Якщо є сумнів, чи продукт безпечний — виключаємо.
3. **Вертикальні зрізи замість горизонтальних.** Краще одна повна фіча "ручний ввід → рецепт", ніж половина бекенду без фронту.
4. **Епік 6 (фото) — буфер скоупу.** Якщо часу не вистачає, його можна відрізати — MVP від цього не помре.
5. **Тиждень 4 — buffer для bugfix-ів.** Не планувати на нього новий функціонал.
