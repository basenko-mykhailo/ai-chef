## Issues found

| # | Test case | Step | Severity | Description |
|---|-----------|-----:|----------|-------------|
| 1 | TC-001 / TC-004 | 4 / 3 | minor | Disclaimer verb is inconsistent: home footer uses `AI може **помилятися**` (imperfective) while the dashboard banner uses `AI може **помилитися**` (perfective). Pick one wording across the layout. |
| 2 | TC-001 / TC-004 | 4 / 3 | minor → major | Disclaimer scope differs: home footer mentions only `склад страв на алергени.`, while the dashboard banner adds `та інші дієтичні обмеження.`. PRD calls out allergens **and** dietary constraints — the home-page copy is less complete and should match the dashboard banner. |
| 3 | TC-005 | — | major | `Log Out` is rendered as a plain anchor (`<a href="/logout">`) hit via HTTP GET. Laravel Breeze's stock template POSTs to `/logout` with a CSRF token; the current GET-style logout works but is vulnerable to logout-CSRF (e.g. an `<img src="/logout">` on a third-party page would end the user's session). Worth verifying in `routes/web.php` / the nav blade. |

## Recommendations

1. **Add per-section content tests** for `/pantry`, `/recipes`, `/history` once those epics ship — at the moment three of four nav targets render the same placeholder, so TC-006 only checks routing, not functionality.
2. **Localise dashboard chrome to Ukrainian.** The page heading is still `Dashboard` and the body says `You're logged in!` — both are Breeze defaults that conflict with the rest of the Ukrainian UI (`Комора`, `Сім'я`, etc.).
3. **Add negative auth cases as the app grows:** registration with an existing email, registration with mismatched password confirmation, password reset flow, rate-limit on the login endpoint.
4. **Cover the AI safety disclaimer explicitly** with a dedicated case (`TC-007 — Disclaimer present on every authenticated page`) once more pages exist — it's a PRD-mandated non-negotiable.
5. **Seed a fixture user** via a `DatabaseSeeder` entry (or an `php artisan` command) so future `qa-run` invocations do not depend on the test user being created ad-hoc through `tinker`. Idempotent seeding would also let the suite run on a freshly reset DB.
6. **Consider a `QaResetState` route** (gated to non-production) that clears cookies / kills the session — would simplify the "anonymous session" precondition handling in `qa-run` and remove the need to walk through the user-menu logout.
