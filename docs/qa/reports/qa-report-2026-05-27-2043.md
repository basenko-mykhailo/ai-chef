## Recommendations

- **Fix `family.index` view.** Either create `src/resources/views/family/index.blade.php` (Epic family-members work, per `docs/tickets/plan.md`) or, if the screen is not implemented yet, temporarily render `placeholder.blade.php` like the other not-yet-built sections appear to. The data layer is already wired (`family_members` query executes), so a minimal placeholder unblocks the smoke test immediately.
- **Add smoke coverage per section.** TC-006 only asserts HTTP 200 on the four nav routes. Once a section is implemented, add a per-section test case (e.g., `TC-00X: /pantry lists current pantry items`) — the template in `docs/qa/_test_case_template.md` is ready to copy.
- **Cover the cooked-flow and recipe-generation paths.** Both are explicit product rules in `prd.md` (atomic decrement of pantry items, ≤10 generations/hr) but have no QA cases yet; add them as Epic 3/4 ships.
- **Localization smoke.** The user-facing locale should be `uk` per `CLAUDE.md`, but `.env` still defaults to `en` — add a Localization-type test that asserts a Ukrainian copy string (e.g., the dashboard heading) once the locale switch lands.
- **Cookie isolation for QA.** The `qa-run` flow currently relies on a CSRF-aware POST to `/logout` to reach the anonymous state because Playwright MCP persists context across `browser_close`. Worth either documenting this in the skill or adding a `clearBrowserContext`/incognito helper.
