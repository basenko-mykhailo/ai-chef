## Recommendations

- **Disclaimer copy consistency (minor).** The anonymous footer says `AI може помилятися` while the authenticated layout's safety note says `AI може помилитися`. Both forms are accepted Ukrainian, but pick one and apply it across templates — current state risks subtle copy drift over time. The PRD/plan only mandates "AI may make mistakes — verify allergens yourself", not a specific spelling.
- **Logout UX coverage.** The QA suite has no case that exercises a logout link/button from the user menu — TC-003 / TC-005 currently rely on POSTing to `/logout` with the CSRF token manually. Add a `TC-007` that clicks `Test User → Log out` (or whatever the menu exposes) and asserts redirect to `/`.
- **`/pantry`, `/recipes`, `/history` content coverage.** TC-006 only asserts that routes don't 500; the placeholder string `Цей розділ незабаром з'явиться.` is visible on three of four sections. Once Epic 2/3 ships add per-section cases (pantry CRUD + photo upload limits per PRD, recipe list, history of cooked recipes).
- **`/family` real content.** `/family` already renders a sample member (`Тато`) — confirm whether that is seeded fixture data or hardcoded markup, and add a case covering add/edit/delete of family members + AND-combine of dietary constraints per PRD.
- **Rate-limit and AI generation flows.** PRD calls for 10 generations / hour / user and a "cooked" flow with atomic pantry decrement; both are zero-coverage in the current test plan.
- **Localization.** `.env` still defaults to `en`; once locale flips to `uk` per CLAUDE.md, add a case asserting page lang/locale and that mixed-language strings (`Dashboard` heading, `Log in` button, `Forgot your password?`) localize correctly.
